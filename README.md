## 1. Engineering problem
Indoor CO₂ is a key input to building HVAC systems: ventilation is often controlled from CO₂ readings, so
missing or faulty readings affect how well a space is ventilated. Monash's environmental sensor data contains
such gaps and faults. This project asks:

**Can missing values in C02 readings be reasonably reliably reconstructed using interpolation?**

Real readings are hidden to create artificial gaps from 10 minutes to 24 hours, reconstructed with three
interpolation methods, and compared with the hidden values. Scope: one sensor (6012002000869), CO₂ only,
29 Feb – 14 Jun 2024. See §1 of the [report](report/MMA3001_Report.pdf).

## 2. Inputs and outputs
- **Input:** the Monash environmental sensor CSV (not included – see [`data/README.md`](data/README.md)). Readings are
  stored as JSON with Unix timestamps and converted to Melbourne time. After removing repeated uploads, sensor
  6012002000869 gives 13,800 CO₂ readings (ppm), normally 10 minutes apart.
- **Outputs:** reconstructed CO₂ values (ppm) for each artificial gap, and per-gap scores: mean absolute error (MAE),
  RMSE, maximum error, bias, overshoot beyond the surrounding readings, and time per fill.
- **Missing or invalid inputs:** missing values and times are dropped; duplicate times, unknown methods or too few
  readings around a gap raise a clear error.

Full table: Table 1 of the report. Function-level inputs and outputs: the HTML documentation in [`docs/`](docs/).

## 5. Usage

1. Complete the setup above, including placing the raw data files in `data/raw/`.
2. Open the notebooks in VS Code (or Jupyter) and select the `.venv` kernel.
3. Run each notebook from the top (**Restart**, then **Run All**). The numbers give the order the work was
   done in, and each notebook loads the raw data itself, so each can also be run on its own:
   - `01_data_audit.ipynb` – explores the raw data.
   - `02_cleaning.ipynb` – applies and checks the cleaning step.
   - `03_gap_filling.ipynb` – the main experiment. It takes a few minutes, mostly loading the data and
     running the experiments.

The functions the notebooks use are in `src/mma3001/` (`io.py` loads the data, `cleaning.py` removes repeated
uploads, `gapfill.py` makes and fills the gaps and scores the methods).

**Settings and the final test (notebook 03):** every setting is in the *Settings* cell (section 1) and is
explained in the decisions log (Appendix A of `report/MMA3001_Report.pdf`). The settings were chosen using development data only.
The final test on the held-back data (section 9) runs only when `RUN_TEST = True`. It was run once, after the
settings were fixed. Rerunning it with the same settings and seed gives the same results. If any setting is
changed, the test data is no longer an independent test.

## 8. Approach and results
- **Methods:** linear interpolation (baseline), exact cubic spline (SciPy `CubicSpline`, not-a-knot) and cubic
  smoothing spline (SciPy `make_smoothing_spline`, λ = 0.1).
- **Validation:** real readings are hidden and used as the ground truth. The series is split by time into 75%
  development data (used to choose all settings) and 25% test data (run once at the end), with a 1-day buffer.
  Every method fills the same 200 random gaps per gap length. The benchmark is the ±75 ppm CO₂ sensor accuracy
  required by ANSI/ASHRAE 62.1 (Allsbrook, 2024). The code is checked by 90 pytest tests.
- **Results (test data, MAE):** linear 7.1–20.0 ppm and smoothing 6.5–40.3 ppm across gaps of 10 min – 24 h, so both
  stay within ±75 ppm on average; the exact cubic spline reaches 237 ppm and gives physically implausible values
  for long gaps. Linear and smoothing are effectively tied up to 2 h; linear is more accurate from 4 h.
- **Optimisation:** fixing λ = 0.1 made the smoothing spline 14–15% more accurate than automatic λ (GCV) for
  8–24 h gaps and 5× faster. Profiling showed most run time is pandas overhead rather than arithmetic.
- **Recommendation:** linear interpolation – the most accurate for long gaps, never implausible, and the cheapest.

Details: §3–5 of the [report](report/MMA3001_Report.pdf) and notebook 03.

## 9. Limitations
- One sensor, one room and one season; results may differ elsewhere.
- Artificial gaps are placed at random and may not behave like real outages.
- The "truth" is the sensor's own reading, which itself has a tolerance.
- No interpolation method can see the daily cycle inside a long gap.
- MAE is an average: individual reconstructed readings in long gaps can still exceed ±75 ppm.

Limitations and lessons learned are discussed in §6 of the [report](report/MMA3001_Report.pdf).
